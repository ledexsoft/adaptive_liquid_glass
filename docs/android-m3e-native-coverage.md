# Native Android Material 3 Expressive coverage

Android adaptive controls in this package use the package-owned Jetpack Compose bridge (`AndroidM3EPlatformView` and native Compose overlays). The Flutter `material_3_expressive` dependency and public catalog re-export have been removed. iOS behavior remains on its existing UIKit/Cupertino paths.

## Implemented routes

| Package API | Android implementation | Flutter content or limits |
|---|---|---|
| Buttons, icon buttons, switches, checkboxes, radio buttons, sliders | Compose Material 3 Expressive controls | Buttons use native pressed-shape morphs and size-based typography, icon spacing and padding; `androidSize` exposes all five button heights. Circular custom corners retain the native morph, while elliptical custom corners use a real Compose button and a fixed exact `GenericShape` throughout press. Icon buttons use five native sizes, three widths per size, token icon dimensions and native round/square pressed/selected shapes. Button content must be serializable text/icons. Switches and switch list tiles can show optional native checked/unchecked thumb icons using `SwitchDefaults.IconSize` and native state colors. `AdaptiveSlider` uses native `SliderState` for drag updates and a Compose `Label`/`PlainTooltip` anchored to its thumb when a label is supplied; `AdaptiveSlider.vertical` uses the real Compose `VerticalSlider` and its vertical thumb token. Both orientations accept optional `centeredTrack` and render Compose's real `SliderDefaults.CenteredTrack`; the default remains the native regular track. `AdaptiveRangeSlider` uses Compose `RangeSliderState`, two real thumbs and optional native labels; other platforms use Flutter's `RangeSlider`. Explicit checkbox/radio focus or hover colors use Flutter's control because Compose exposes no separate overlay-color parameters for them. |
| Filter and input chips | `AdaptiveFilterChip` delegates to Compose `FilterChip`/`ElevatedFilterChip`; `AdaptiveInputChip` delegates to Compose `InputChip`; each uses its official `shapes()` defaults | Selection, pressed morph, colors, ripple, focus and accessibility use the native components; Flutter controls selected values. Filter chips expose native leading and trailing icon slots. Input chips support whole-chip dismissal with the native trailing close icon and accept either an icon or image in the official avatar slot. The image takes precedence over an avatar icon, which takes precedence over a leading icon; an image reserves its slot while decoding and uses circular crop. Flutter Material chips render on other platforms or when an icon cannot cross the bridge. Capped Kotlin compilation passes; device image decoding and interaction remain pending. |
| Assist and suggestion chips | `AdaptiveAssistChip` and `AdaptiveSuggestionChip` delegate to their official flat/elevated Compose components | These are action chips with a single native `shape` parameter, rather than the selected/pressed `ChipShapes` overload. Compose owns their state colors, elevation, border, padding, icon size, ripple, focus and semantics. Other platforms use Flutter `ActionChip`; device interaction remains pending. |
| Button groups, split buttons, toolbars, FABs and FAB menus | Official Compose expressive components, including five button-group and split-button size tokens, filled/tonal/outlined/elevated split styles, `FlexibleBottomAppBar`, `HorizontalFloatingToolbar`, `VerticalFloatingToolbar`, and adaptive app-bar overflow | Button groups expose standard/connected layouts, selection-required behavior, width morphing, keyboard navigation, and native tooltips for supplied action descriptions. Standalone FABs expose real small (40 dp), standard (56 dp), expressive medium (80 dp), and large (96 dp) Compose variants through `androidSize`; `mini` keeps its existing default mapping. Extended FABs use Compose's animated `expanded` overload and keep the Flutter host wide until the native collapse finishes. FAB menus expose 2–6 labeled actions, localized toggle semantics, RTL corner alignment, and initial close-button focus. Split buttons keep a 48 dp minimum target for XS/S, a checked-state shape morph, theme-scheme rotating chevron, and trailing-segment menu anchoring. See [button-group and FAB-menu coverage](android-m3e-button-groups-fab-menus.md), [split-button coverage](android-m3e-split-buttons.md), and [toolbar coverage](android-m3e-toolbars.md). |
| Tabs, segmented controls, navigation rail, app bars, bottom navigation | Compose Material 3 Expressive navigation controls, including primary/secondary fixed and scrollable tab rows, `TopAppBar`, centered small, medium/large flexible, native app bar search, `NavigationBar`, and `ShortNavigationBar` | App bars support title/subtitle alignment, encoded logos, one filled/tonal action, search suggestions and callbacks, responsive overflow, explicit leading/action icon size and tint, and Flutter scroll notifications bridged to native collapse/color behavior. Unsupported Flutter icon effects retain the framework app bar. Android tabs default to the primary text row; `androidRowStyle` selects the secondary hierarchy, `androidIcons` adds real Compose icons, and `androidShowLabels: false` makes icon-only tabs with accessible names from `tabs`. The fixed row is used when labels fit; the real scrollable row handles overflow. The Flutter `PageView` remains the content owner. Segmented controls follow Compose's measured height and, with `shrinkWrap`, its intrinsic width. Bottom navigation keeps native disabled semantics when no callback is supplied, visible labels unless hidden or intentionally blank, caller-specified unselected icon/label colors, and explicit normal/selected icon size and tint. An icon-only destination needs a localized `Icon.semanticLabel` in both states; its real Compose item omits the label slot. Count badges accept an optional localized description for accessibility. The optional short bar uses Compose's compact equal-weight and medium centered layouts. See [app bar coverage](android-m3e-app-bars.md). Scaffold/page structure and arbitrary page content remain Flutter-owned. |
| Carousels | Native Compose hero, multi-browse, uncontained, and multi-aspect layouts | Android callers supply serializable `androidItems` (including encoded image bytes); Flutter `children` are used on other platforms. Native item masks follow the carousel's focal resize, tapping an item animates it toward the focal position, and position callbacks wait for scrolling to settle. The clickable Card merges its visible text for accessibility unless a caller supplies `semanticDescription`. Default item spacing, outer padding, hero width and corners come from Compose/theme; callers can override them, and an explicit tap duration uses Compose animation. Android supports snapping or free scrolling. Multi-aspect items use individual `mainAxisExtent` sizes and the native AndroidX parallax modifier on a `LazyRow` or `LazyColumn`; this variant always scrolls freely. Its default 8 dp gap and 16 dp padding follow the official Compose sample. Unsupported `isExtended: true` and noncenter `heroAlignment` now report an error instead of silently doing nothing. The pinned Compose release does not expose the guide's vertical full-screen carousel as a Material 3 carousel composable. |
| Badge, divider, progress and loading indicators | Native Compose badges, `HorizontalDivider`/`VerticalDivider`, linear/circular progress, and loading indicators | `AdaptiveDivider` and `AdaptiveVerticalDivider` use the official Material thickness/color defaults or caller overrides, with axis-specific insets. Their decorative Android hosts use transparent hit testing so overlays do not intercept touches. Progress supports determinate/indeterminate modes, flat/wavy shapes, accessible labels, configurable thickness and M3 color roles. The shape-morphing loading indicator supports both looping and determinate progress through official Compose overloads. See [progress-indicator coverage](android-m3e-progress-indicators.md). Badge can decorate Flutter child content and accepts an optional contextual accessibility label for its native visual. Its Flutter host now follows the actual Compose `Badge` size and keeps the `BadgedBox` anchor even when the label is wider than the decorated child. |
| List tiles, switch list tiles, expansion headers, and search suggestions | Expressive Compose `ListItem` and `SegmentedListItem` overloads, plus native `Switch` | Native selection, disabled colors, click feedback and shape motion come from Compose. `AdaptiveListTile` can supply a segment index/count to use the real segmented variant. The switch row toggles as one control when no separate tile action is supplied; its leading icon keeps explicit size, tint and semantic label in Compose. Flutter hosts use the 56/72 dp list tokens plus required padding and text-scale space; titles/subtitles use plain `Text` and icons must be serializable. See [list coverage](android-m3e-lists.md). |
| Popup and context menus | Compose `DropdownMenu` in the Android window | Flutter anchors remain Flutter; menu rows are serialized. |
| Popup menu with custom Flutter child anchor | Compose `DropdownMenu` in the Android window | The anchor remains Flutter; menu rows, images, enabled state, subtitle, and selection are serialized. |
| Navigation drawer | Compose `ModalNavigationDrawer`, `ModalDrawerSheet`, and `NavigationDrawerItem` through `AdaptiveNavigationDrawer` | Flutter Scaffold keeps `openDrawer()` compatibility and edge gesture initiation. Its automatic width is responsive and shared by the Flutter gesture placeholder and native modal; explicit width is bounded to 240–360 dp when space permits and capped by the available window width. Drawer state drives close animation and predictive Back before destination events close the Flutter overlay. The end drawer changes sheet placement while preserving the app's text direction inside it. The header is a native accessibility heading, and item padding comes from `NavigationDrawerItemDefaults`. Destination badges accept an optional localized description. Disabled destinations retain the native item while the bridge blocks input and exposes disabled semantics; device TalkBack verification remains. Caller-supplied custom drawer widgets remain Flutter content. |
| Alert/input dialogs, action sheets, date/time pickers | Compose dialogs, official `ModalBottomSheet`, picker controls, and package-owned Android modal host | Alerts use a single native `AlertDialog` window and its responsive action flow. Input alerts pass Flutter keyboard requests into the real Compose outlined or secure field; `TextInputType.none` keeps Flutter's no-keyboard field behavior. The action sheet uses the unified native sheet state, Compose defaults and expressive list actions; selection waits for the native close animation. Date/time actions receive localized labels and both picker views supply Flutter's app locale through their Android `Context`, so native calendar, title/headline and time labels use that locale. Compose has no public initial year-grid mode, so year-first and month-year requests use Flutter's actual Material year picker; native locale and RTL rendering still need device checks. Time selection uses official `TimePickerDialog` on compact screens and `VibrantTimePickerDialog` on larger screens, with dial/input switching and validity-gated confirmation. Callbacks and results cross as serializable events. |
| Search bars and text fields/form fields | Compose Material 3 text controls | The standalone search bar uses the current Material localization for its default hint and preserves an explicit override. Optional `androidSuggestions` activates the state-based native `SearchBar` with `ExpandedFullScreenSearchBar` below 600 dp or `ExpandedDockedSearchBar` at medium and larger window widths, real `ListItem` results, Material expansion/collapse motion and a localized Back action; omitting it retains the compact-only route. Text fields use native state-based editing and secure input, with Flutter controller/selection/composition, formatters, focus, validation and reset bridged. Expressive rounded shapes and a character counter are native. Prefix/suffix content must be plain text or serializable icons; explicit icon size, color and semantic label reach Compose. Decoration icon colors that vary by focus, error or disabled state use the native `OutlinedTextFieldDefaults` color roles. Flutter-only icon effects and hover-specific or incompatible combined-state color rules retain the Flutter field. |
| Snackbars and tooltips | Compose Material 3 `Snackbar`, `PlainTooltip` and `RichTooltip` in Android overlays | Tooltip anchor is measured by Flutter; Material 3 draws and positions the tooltip. `androidTitle` and an optional labeled action select the real native `RichTooltip`; the action runs after its exit animation. Supported explicit text weight, italic style, letter spacing, line height and font family reach native tooltip text, as do circular custom corners through each tooltip's `shape`. Explicit glyph fallback lists and unsupported visual effects retain Flutter rendering. |
| Cards and form sections | Compose `Card`, `ElevatedCard` or `OutlinedCard` surface underneath Flutter content | An explicit `AdaptiveCard.style` selects the matching real Compose variant and its own color, elevation, shape and outline tokens; omitted style preserves the previous filled Android card. Explicit asymmetric and elliptical corners are passed to the native shape, including RTL resolution. An explicit border uses native `Card.border` when behind the child; the default foreground order draws only that caller border in a pointer-transparent Flutter overlay above the clipped child. Arbitrary child widgets and card taps remain Flutter-rendered. Tappable cards forward paired press/release/cancel, hover enter/exit and focus/unfocus events to the native clickable card interaction source. Flutter owns Enter/Space activation while the native card suppresses its empty keyboard target; opaque Flutter children can cover the underlying ripple. Device timing, child hit testing, focus order and accessibility still need verification. Flutter child clipping follows the optional Compose medium shape radius; other custom native shapes need device review. |
| Expansion tile | Compose `ListItem` header and native icon/control; expanded body is Flutter content | Header title/subtitle must be serializable `Text`; leading/trailing Material icons forward explicit size, color and semantic label. Flutter icon effects that cannot cross the native bridge keep the framework `ExpansionTile`. |
| Pull-to-refresh | Compose `PullToRefreshDefaults.LoadingIndicator` | Flutter `RefreshIndicator.noSpinner` detects scroll/edge gestures and invokes `onRefresh`; its drag distance drives the real Compose progress morph. Compose animates the official indicator to the threshold and back to hidden, with the native 56 dp default center or an explicit caller displacement. A localized or caller label and optional value reach native semantics. The Flutter child is not a Compose `PullToRefreshBox`. |
| Blur / Liquid Glass | No Android glass effect is claimed; standalone `AdaptiveBlurView` does not draw a Flutter blur on Android, while `AdaptiveCard.glass` uses a native Material surface | Android cannot natively blur Flutter-rendered content behind a platform view. Liquid Glass remains an Apple-platform feature. |

The standalone Android `AdaptiveSwitch` host now follows Compose's 52 dp track width and reserves a 48 dp height for its native touch target. Switch rows remain measured by their real Compose `ListItem` layout. The small native FAB keeps its 40 dp visual surface inside a 48 dp Flutter host so Compose's minimum interactive size is not clipped. Standalone Android FABs require a nonblank `tooltip` or `Icon.semanticLabel` so their icon action has an accessible name; this applies to both the native route and an unsupported-icon-style Flutter fallback.

`AdaptiveTooltip.androidPosition` optionally selects Compose's above, below, logical start/end, or physical left/right position provider; `androidSpacing` sets its anchor gap. The existing `preferBelow` route remains the default. An explicit native position requires native-compatible text and decoration so it is not silently discarded by a Flutter fallback.

`AdaptiveTooltip.androidTitle` selects Compose `RichTooltip`; `androidActionLabel` and `onAndroidAction` must be supplied together for its native `TextButton`. `androidCaret` enables the native `TooltipDefaults.caretShape()` on either tooltip variant; `androidCaretSize` optionally sets a positive custom width and height and also enables it. These Android-specific options do not alter iOS or other platforms. The action callback runs once after Compose reports that the tooltip has closed.

With no explicit `expandedWidth`, the expanded Android navigation rail follows the real `WideNavigationRail` measured width within its 220–360 dp tokens. Flutter clips its host to the reported width while retaining a full native measurement viewport, so Compose owns the width spring and item layout.

## Native bridge and toolchain

- Android minimum SDK: 24.
- Compile SDK: 37.
- Compose Material 3: `1.5.0-rc01`; Compose UI: `1.12.0`.
- Android Gradle Plugin: 9.1.1; Gradle wrapper: 9.3.1; Kotlin: 2.4.20; JDK: 17+.
- Flutter: 3.47+; the global Flutter installation used for the example build is 3.47.9.

Compose cannot mount an arbitrary Flutter widget subtree. The APIs that accept content models serialize supported data and fail clearly when an unsupported custom widget is supplied; hybrid surface/layout APIs keep arbitrary child content on Flutter while their Android control or visual surface is native.

## Review against Material 3 Expressive

| Foundation / update | Status | Notes |
|---|---|---|
| Expressive color and dynamic color | Applied; device verification pending | Native Compose uses `MaterialExpressiveTheme`. Android 12+ wallpaper colors are enabled by default; callers can disable them with `AdaptiveMaterialExpressiveTheme(dynamicColoring: false)`. On Android 7–11 the bridge generates a complete expressive fallback scheme from the host primary using Flutter's bundled Material Color Utilities and applies its roles to the real Compose theme. |
| Expressive motion | Native Compose controls use the M3 system; package-owned hybrid transitions use matching Flutter physics | The Compose theme explicitly selects `MotionScheme.expressive()`, so native Material controls use its spatial and effects specs. Android tab selection/swipe settling and expansion content use Flutter spring simulations with the corresponding M3 spatial token values because their content is Flutter-rendered. Material currently lists Jetpack Compose as available and Flutter as unavailable for its motion system, so these hybrid paths are token-matched Flutter physics, not the official M3 Flutter implementation. Programmatic transitions honor reduced motion; finger-driven swipes retain spring settling. Arbitrary app-owned Flutter child animations do not inherit Compose's spring specs. |
| Updated and new components | Broad native coverage | The package routes its Android adaptive controls to official Compose Material 3 components, including button groups, split buttons, FAB menus, floating toolbars, carousels, loading/progress indicators, and wide navigation rail. This does not mean every Material component is exposed as an adaptive package API. |
| Typography | Type roles and declared font assets bridged; device checks pending | The active Flutter `TextTheme` supplies size, weight, style, tracking, line height and family for all 15 baseline roles in Compose's real `MaterialExpressiveTheme`. `AdaptiveMaterialExpressiveTheme(typography: ...)` additionally applies the baseline scale to Flutter and supplies all 15 emphasized roles to Compose; `AdaptiveApp` forwards a scale registered in its active Material theme. Android resolves families declared in the consuming app's `FontManifest.json` using Compose's asset `Font` API and the Flutter engine's asset paths. Per-widget text slots and fields use the same resolver, followed by Compose's optional device-font lookup for installed Android families. On API 26+, declared variable-font families receive theme-role axes and qualified per-widget axes; API 24–25 uses the static face. Common OpenType `fontFeatures` reach theme roles, supported native text slots and text fields. Unspecified roles retain Compose defaults. Ordered glyph fallback and per-widget axes without an explicit family remain on Flutter; large-font and device rendering checks remain. |
| Expanded shape library | Covered by opt-in APIs | `AdaptiveExpressiveShapeView` exposes the complete 35-shape `MaterialShapes` catalog and native Compose `Morph` between any two catalog entries on Android. `AdaptiveExpressiveShapeScale` optionally overrides all eight rounded-corner roles in the real Compose `Shapes` theme; unspecified roles retain native defaults. The catalog view and theme scale are separate, and existing widgets keep their component defaults unless the caller opts in. |

The package therefore applies the native expressive theme and a broad set of expressive components, but does not reproduce every design-system resource or expose every component in Google's catalog. Font asset and variable-axis rendering still need device checks; ordered per-widget glyph fallback and axes without an explicit family remain typography gaps. Shape catalog rendering and catalog-to-catalog morphing are available through the opt-in `AdaptiveExpressiveShapeView` API.

## Verification status

The full Flutter suite passed all 838 tests on 2026-11-11, serially with `--no-pub --concurrency=1`, after the small FAB-menu close-button, accessible-label, split-button label, icon-only navigation and rail, and blank drawer-slot corrections. All 11 focused FAB-menu, 14 focused split-button, 12 focused bottom-navigation, 15 focused rail and 15 focused drawer tests and full `flutter analyze --no-pub` also passed. The capped offline example Android `:app:assembleDebug` passed after the native 56 dp slot correction; the later navigation and drawer Kotlin changes passed capped offline `:adaptive_liquid_glass:compileDebugKotlin`. The pinned AndroidX source showed its close button grows to 56 dp, so the small menu marker and native slot reserve 56 dp for the entire animation. The local Android 37 AVD remained `offline` in ADB after two minutes and logged Hypervisor.Framework/memory-protection errors under both software and host GPU modes. It was stopped to avoid unnecessary RAM use. Native runtime interaction and visual behavior have not been verified on-device.
