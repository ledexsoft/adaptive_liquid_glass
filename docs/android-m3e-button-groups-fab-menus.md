# Android button groups and FAB menus

`AdaptiveButtonGroup` and `AdaptiveFabMenu` use the native Jetpack Compose Material 3 Expressive components on Android. They serialize labels and `AndroidM3EIcon` values across the Flutter/Compose boundary; arbitrary Flutter children cannot be placed inside native buttons.

## Button groups

- `AdaptiveButtonGroupType.standard` uses Compose's 12 dp default gap for every size unless `spacing` is supplied. It hugs its button content and uses the native width spring to expand the pressed button while its neighbors compress. The compression limit follows the native padding for the configured size, style and icon, including RTL. `neighborSquish: false` disables that width interaction.
- `AdaptiveButtonGroupType.connected` fills the available row, uses equal button widths and the official 2 dp gap, applies native leading/middle/trailing shapes, and does not squish neighboring buttons.
- With `direction: Axis.vertical`, connected groups use the native middle-button shape with top-rounded first and bottom-rounded last buttons, including their pressed shapes. The default 6 dp overlap follows the official Compose vertical example. A single connected action uses the standalone native toggle-button shape.
- `AdaptiveButtonGroupSize` exposes XS, S, M, L, and XL. Compose supplies the corresponding height, icon, padding, and expressive shape tokens. The Compose controls keep their minimum interactive target, including the 48 dp target for XS/S.
- Icon-only actions use the real Compose toggle button's content slot at the native icon-size token; labeled actions use its leading-icon slot and native icon/text spacing. Every action must have visible text or an icon in both its unchecked and checked states. On Android, each action also needs a localized `semanticLabel`, `tooltip`, or visible `label`; icon identifiers are not used as accessible names or overflow text.
- The Flutter host reserves the button group's initial height, including each vertical action and its configured gaps, then follows Compose's measured height when labels wrap or native layout changes. This allows groups inside scrollable columns without filling the screen.
- The host also gives horizontal groups a finite initial width from the native size, padding, icon and spacing tokens, so they can be placed inside horizontal rows and scrollers. For bounded standard groups, Compose keeps its native overflow menu when the actions do not fit; bounded connected groups fill their available width. Compose's measured width can refine the host without recreating the view.
- `selectionRequired: true` prevents the last selected option from being cleared, including when it appears in the native overflow menu. Overflow choices use real Compose `SelectableDropdownMenuItem` or `CheckableDropdownMenuItem` according to the selection mode, with native selected shape/color transitions and RadioButton/Checkbox semantics. A valid choice closes with Compose's `DropdownMenu` exit transition before the selection callback reaches Flutter. `selectedIndex` / `selectedIndices` remain caller-owned state; use the corresponding callback to update them.
- If the matching selection callback is absent, the group is read-only: its real Compose toggle buttons and overflow trigger are disabled. The Flutter fallback chips follow the same rule. Supply `onSelectedIndexChanged` for single selection or `onSelectedIndicesChanged` for multi-selection to make the group interactive.
- In single-select groups, `selectedIndex` takes precedence over action-level `checked`; without it, the first checked action is selected. In multi-select groups, `selectedIndices` takes precedence over the checked actions. Flutter and Compose follow the same precedence.
- Buttons carry their label and selected state to accessibility services. Tab and arrow keys follow Compose's native focus navigation across visible horizontal actions and the overflow control; the group container is not an extra focus stop. Vertical groups handle Up and Down between enabled actions. Verify the full traversal with a physical keyboard on Android.
- A nonempty action `tooltip` uses the native Compose `TooltipBox` and `PlainTooltip` on Android, anchored to its toggle button. Compose handles long press, hover and keyboard focus. The tooltip text also serves as an accessibility-description fallback when `semanticLabel` is absent.
- Connected horizontal groups use Compose's 2 dp token; connected vertical groups follow the official 6 dp overlap example. A supplied `spacing` replaces the default.

The non-Android fallback remains Flutter-rendered and uses `FilterChip`; native connected morphing and Compose motion only apply on Android.

## FAB menus

- The menu accepts 2–6 related actions, each with visible text and an icon. The native toggle FAB opens the official Compose menu, and item actions close it before invoking callbacks.
- The small toggle starts as a 40 dp native visual and grows to the official 56 dp close button. A centered 56 dp Compose button slot and matching Flutter `Scaffold` marker reserve room for the full animation and the 48 dp minimum touch target; medium and large retain their existing 56/96 dp slots.
- `toggleMenuLabel`, `closeMenuLabel`, `expandedStateLabel`, and `collapsedStateLabel` default to the host's `MaterialLocalizations` and can be overridden by callers. An explicit override must contain non-whitespace text so the native toggle keeps its accessible name or state. The toggle's tooltip, pane title and accessibility name describe opening or closing according to its current state. The close control is part of the native menu, receives initial keyboard focus, and is first in accessibility traversal. The last item also exposes a custom accessibility action to close the menu, following the official Compose sample. From the first item, Up, numpad Up or Shift+Tab returns focus to the close control. Back and Escape close the menu.
- `left`/`right` use logical start/end alignment, so the menu mirrors with RTL. Compact windows use 16 dp margins; windows at least 600 dp wide use 24 dp.
- Native menu items keep both their text and icon. An action's explicit Flutter `Icon.size` and `Icon.color` reach its native icon slot; omitted values retain the Compose item defaults. Explicit sizes and colors on the opening and closing toggle icons become endpoints of Compose's native icon-size and icon-color interpolation; omitted endpoints keep the Material tokens. By default, a Flutter `OverlayPortal` leaves a normally sized FAB marker in `Scaffold` and positions one full-size native Compose view over it. The official `FloatingActionButtonMenu` remains mounted while opening and closing, so its native staggered motion can run in both directions. The toggle uses the Compose size, corner, icon-size and palette-color interpolation helpers. Explicit background and foreground colors stay fixed through the transition. Short-window overflow and oversized action icons still need device verification.

`useFullScreenOverlay: true` skips the package's overlay host and uses the caller's full bounds. Use it only inside a bounded screen overlay such as `Positioned.fill` in a `Stack`; placing that full-size view in `Scaffold.floatingActionButton` changes Scaffold's FAB measurements and can displace floating snackbars.

The current package API places the native menu at its selected screen corner; it does not expose an arbitrary Flutter anchor point or expansion target for each action.

## Motion

The Android Compose subtree inherits the package's `MaterialExpressiveTheme` and `MotionScheme.expressive()`. Native button-group width changes and FAB-menu transitions therefore use Compose's spatial/effects springs. The split-button chevron uses the active expressive scheme's fast spatial spring for its small rotation. Flutter-rendered Android transitions continue to use the package's documented M3-token-matched spring physics; app-owned Flutter animations do not inherit Compose motion automatically.
